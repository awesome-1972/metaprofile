# Специфікація звіту по кандидату (#41)

Джерела клієнта (отримано): промт оцінки (CAE), приклад фінального звіту, матриця оцінки `Risk_Officer_Matrytsia_Otsinky_Dashboard.xlsx` (CRO).

## 1. Механіка оцінки компетенцій (з матриці)
- **Шкала 1–3:** 1 — проявлена слабо; 2 — достатній робочий рівень; 3 — сильно та стабільно.
- **Структура:** 4 групи компетенцій × по 5 компетенцій = 20.
  - Ціннісні / Value
  - Професійні / Professional
  - Лідерські / Leadership
  - Особисті / Personal
- **Ваги:** кожна **група = 25%**; кожна **компетенція всередині групи = 20%** (5×20% = 100%).
- **Оцінка групи** = середнє з 5 її компетенцій.
- **Загальна** = сума (оцінка групи × 25%) по 4 групах.
- **Кожна компетенція** має приклади інтерв'ю-питань (є в матриці — можна показувати рекрутеру під час оцінки).

## 2. Рівні відповідності — Є РОЗБІЖНІСТЬ (треба рішення)
- **Дашборд матриці:** Сильна ≥ 2.5 · Хороша ≥ 2.0 · Часткова ≥ 1.5 · Низька < 1.5.
- **Промт (Додаток A, уже в нашому Edge):** Висока 2.34–3.00 · Середня 1.67–2.33 · Низька 1.00–1.66.
- **Треба вибрати єдину шкалу рівнів.** За замовчуванням візьмемо дашбордну (2.5/2.0/1.5), бо це файл механіки; легко переключити.

## 3. Промт
Отримано повний промт (senior Executive Search консультант, українською, доказовість, факт/оцінка/припущення, структура звіту на 6 розділів, критичні зони). Завантажується як **дефолтний промт** kind=candidate_report у редакторі промту вакансії. Промт рольовий (CAE) — для інших ролей редагується у вкладці «Звіти».

## 4. Шаблон фінального звіту (структура)
1. Загальний рівень відповідності (середньозважена + рівень + резюме 5–7 речень).
2. Сильні сторони (4–5, з прикладами).
3. Зони ризику та неспівпадіння (2–3, зі статусом ризику).
4. Оцінка за компетенціями (зведена таблиця 4 груп + деталізація 4.1–4.4).
5. Технічна інформація (таблиця параметрів; «не уточнено» якщо нема).
6. Висновок і рекомендація (одна з 4 + аргументи + ключовий ризик + що перевірити).

## 5. Що вже є в системі
- Звіт **прив'язаний до заявки** (кандидат-на-вакансію) — `candidate_reports.application_id`.
- Edge `generate-candidate-report` збирає: бріф/опис вакансії + матрицю компетенцій (`vacancy_competencies`) + оцінки (`competency_scores`, зважено, пороги Додатку A) + транскрипт + промт (`vacancy_prompts`).
- Пороги Додатку A вже в коді (= варіант промту, не дашборду).
- Редактор промту вакансії у вкладці «Звіти».
- **Редагування фінального звіту** перед відправкою — ✅ зроблено (текст правиться в діалозі перегляду й зберігається в `candidate_reports.content_md`).
- «Версія для клієнта» — брендований HTML → друк у PDF.

## 6. Що лишилось по #41
- **(A)** Налаштувати матрицю компетенцій вакансії за цим шаблоном: 20 компетенцій, 4 групи × 25%, компетенція × 20%, + приклади питань. Джерело — засівати з шаблону/довідника при створенні матриці; ваги за замовчуванням.
- **(B)** Узгодити шкалу рівнів (див. п.2) — вибрати одну; оновити Edge + дашборд.
- **(C)** Завантажити промт клієнта як дефолт kind=candidate_report.
- **(D)** Керований **шаблон звіту** (структурні секції) — щоб можна було міняти без правки промту.
- **(E)** Доставка клієнту — розширити поточний PDF.

## 7. Варіанти доставки клієнту (пропозиція)
- **PDF (є)** — брендований, через друк. Наступний крок — server-рендер PDF (стабільніший за друк).
- **DOCX** — редагований Word для клієнта/рекрутера.
- **Захищене посилання** — сторінка звіту за токеном (як публічний бріф), завжди актуальна версія.
- **Email клієнту** — напряму через Resend (з PDF/лінком у вкладенні).
- **Google Doc** — експорт у Drive для спільного редагування.
- Рекомендація: спершу **server-PDF + email + захищене посилання**; DOCX/Google Doc — за потреби.
