# Живий профіль досягнень кандидата (dynamic, evidence-based)

**Дата:** 2026-08-31. Мета: профіль кандидата не статичний — його навички й цінність
**накопичуються з реальної активності** (кейси, навчання, оцінювання). Роботодавець у пошуку
знаходить не резюме, а **доказові свіжі досягнення**.

## Принцип (узгоджено з візією)
Первинний промт: «жодної гейміфікації та емоційного тиску». Тому це **не** аркадна гейміфікація
(бали/XP/значки/ліги/стріки), а **накопичення доказів**: кожна навичка підтверджена реальним
результатом, з датою і поясненням «як розраховано». Усе вторинне до людського рішення.

## Механіка — 5 елементів
1. **Граф навичок із доказами.** skill → рівень, виведений з активності; біля кожної «чим
   підтверджено» (кейс/курс/оцінювання, бал, дата).
2. **Стрічка досягнень.** Хронологія верифікованих подій із датами → видно свіжість.
3. **Актуальність і повнота профілю.** Професійні індикатори (свіжість доказів, повнота), без
   «геймерського рахунку» й без тиску.
4. **Цикл зростання.** Виконання рекомендованих кейсів/курсів піднімає рівень навички (прозоро).
5. **Пошук для роботодавця.** Фільтр/ранжування кандидатів за доказовими навичками + свіжістю.

## Модель даних (план)
- `candidate_skill_evidence(id, user_id, skill, level, source_type[case|course|assessment],
  source_id, score, evidenced_at)` — одне джерело істини для навичок з доказами.
- Профіль: `profiles.skills` стає **похідним** (з evidence), а не лише самозаявою.
- Тригери/функції: при завершенні кейсу (`case_submissions` evaluated), курсу, оцінювання —
  апсерт у `candidate_skill_evidence` (рівень = f(score), evidenced_at = now()).
- Індикатор актуальності = f(max(evidenced_at)); повнота = покриття ключових навичок.

## Захисні межі (anti-gamification)
Без балів/XP/монет, стріків, рейтингів-ліг, значків-заради-значків, емоційних нудджів. Лише факт,
дата, «як розраховано», вторинність до людини.

## Роботодавцю (payoff)
Пошук кандидата = демонстровані навички з доказами + свіжість, а не самозаявлене резюме. Це і є
диференціатор проти job-бордів і статичних CV.

## Кроки реалізації (backlog)
1. Таблиця `candidate_skill_evidence` + RLS (кандидат бачить своє; компанія — за доступом).
2. Наповнення: тригер/edge при evaluated-кейсі/курсі/оцінюванні → апсерт evidence.
3. UI профілю: граф навичок із «чим підтверджено» + стрічка досягнень + індикатори актуальності/повноти.
4. Пошук роботодавця: фільтр/ранжування кандидатів за evidence + свіжістю.
5. Проброс у ATS-звіт (як окреме доказове джерело).
