1. Для створення та редагування вакансії використовується ендпоінт POST/vacancy/add.
Нижче є приклад правильного створення вакансії з мінімальним достатнім набором полів.
{
"id": 0, це поле id вакансії: при створенні вакансії завжди залишаємо 0, при редагуванні вказуємо id вакансії, яка редагуватиметься
"cityId": 1, це поле id регіону, під цим id 1 у нас Київ, отримати список id кожного регіону можна за допомогою ендпоінту GET /values/citylist
"rubricList": [25], це поле id рубрики, під цим id у нас рубрика «Морські спеціальності», отримати список id кожної рубрики можна за допомогою ендпоінту GET/values/rubrics  
Цей параметр більш неактуальний і його не потрібно вказувати у запиті. На даний момент рубрики для вакансій проставляються автоматично нашою системою без будь-якої участі з боку користувача як при створенні/редагуванні вакансій за допомогою інтерфейсу сайту, так і при створенні/редагуванні  за допомогою API.
"salary": 15000, це поле розміру заробітної плати у форматі одного цілого значення. Воно необов'язкове, але може бути корисним. Якщо потрібно вказати розмір заробітної плати у форматі діапазону “від” та “до”, то використовуйте параметр "salaryRange"
"salaryRange": { "amountFrom": 100, "amountTo": 200000 },  це поле розміру заробітної плати у форматі діапазону “від” та “до”
"salaryDescr": "ставка та бонуси", це поле коментаря для заробітної плати
 "publishType": "Business", тут вказується тип публікації, який використовується для вакансії, типи бувають "Business", "Optimum", "Professional", "Anonym". Вказуйте той, який є на рахунку і в якому ви збираєтеся публікувати вакансію.
"name": "Водолаз-ілюзіоніст", назва вакансії
"description": "Текст опису вакансії", це поле для тексту опису вакансії, мінімум 150 символів
"sendResumeType": "1", це поле налаштування того, як вакансія буде отримувати відгуки, значення можуть бути наступні: 
1 – це «в розділ \"Відгуки\" на сайті та на вказаний E-mail у параметрі contactEMail», 
3 – це "тільки в розділ \"Відгуки\", 
2 - це "направляти на анкету", В цьому випадку, пошукач натиснувши на кнопку "Надіслати резюме" при перегляді вакансії на нашому сайті, буде перенаправлений за Вашим посиланням. Посилання вказується у параметрі "formApplyCustomUrl":https://www.YourLink.com/ExternalJobseekerForm.
"contactEMail": " name@xxxxxxxxxxx.com ", електронна адреса на яку надходитимуть відгуки. Вказується лише якщо використовується значення 1 у полі "sendResumeType". Якщо в полі "sendResumeType" використовується значення 3 , можна не вказувати поле з електронною адресою .
    "designId": 0, це поле дозволяє вибрати макет у разі публікації вакансії типу Professional, воно є необов'язковим. Замість 0 підставляєте цифру значення Вашого макета, одержати список id кожного макета можна за допомогою ендпоінту GET /notebook/vacancydesign

"contactPerson": "Тарас Шевченко", це поле імені контактної особи. Заповнюється за бажанням
"contactPhone": "+380111111111,+380333333333",  це поле контактних даних, що відображаються у вакансії. Заповнюється за бажанням

"isForStudent" ,  це параметр відображення у вакансії позначки "Розглянемо студентів / без досвіду" де true - це увімкнено, а false - це вимкнено.
"isSpecialNeedsPeople_Enable", це параметр відображення у вакансії позначки "Розглянемо людей з інвалідністю " де true - це увімкнено, а false - це вимкнено.
"isHideInProfile", це параметр  "Не відображати вакансію на сторінці профілю вашої компанії", де true - це увімкнено, а false - це вимкнено.
"endingType" – параметр, який регулює подію яка відбудеться при завершенні терміну публікації вакансії, в якому підтримуються наступні значення:
CloseAndNotify - завершити вакансію та повідомити на email;
AutoRepublish - Опублікувати вакансію автоматично на наступний місяць 1 раз. При завершенні терміну публікації вакансії буде використано одну одиницю сервісу для перепублікації вакансії на новий термін;
*Публікувати вакансію автоматично щомісяця – налаштування доступне тільки за допомогою інтерфейсу сайту.
"scheduleId", це параметр який вказує тип зайнятості: повна - 1, часткова - 2, проектна - 5, позмінна - 7. Відсутня можливість за допомогою API вказати характер роботи його можна вказати лише через інтерфейс сайту. 
Цей параметр втратив свою актуальність, тепер тип зайнятості і характер роботи можна вказувати за допомогою параметрів "employmentTypes" і "workTypes"

"employmentTypes" , це параметр який вказує тип зайнятості: "FullTime" - повна, "PartTime" -  часткова, "ProjectBased" - проектна, "Shift" - позмінна. Можна вказати одне значення або кілька значень.

"workTypes", це параметр який вказує характер роботи:  "Remote" - віддалена, "Hybrid" - гібридна, "Office" - в офісі/на місці. Можна вказати одне значення або кілька значень. 

}
*Фото контактної особи та Додатковий контакт - можна вказати тільки за допомогою інтерфейсу сайту
*Блоки "Переваги вакансії", "Фотографії", "Медіа" -  можна вказати тільки за допомогою інтерфейсу сайту
*Автоскринінг - можна використовувати тільки за допомогою інтерфейсу сайту
2. Редагування вакансії аналогічно до створення, просто в параметрі "id" вказуємо id вакансії, яка буде редагуватися.
3. Щодо процесу публікації вакансії. Після створення вакансії отримуємо її id та за допомогою методу POST /vacancy/state змінюємо її статус на Publicated, тим самим публікуємо її.
Нижче наведено перелік статусів, за допомогою яких можна опублікувати, завершити або видалити вакансію.
    Publicated – Опублікувати вакансію
    Closed – Завершити вакансію
    Deleted – Видалити вакансії
    NotPublicated – Чернетка.

English version of the document
1. To create and edit a vacancy, use the endpoint POST /vacancy/add.
Below is an example of the correct creation of a vacancy with a minimum sufficient set of fields.
 {

"id": 0, this is the vacancy id field: when creating a vacancy, we always leave 0, when editing, we indicate the id of the vacancy that will be edited
"cityId": 1, this is the id field of the region, under this id 1 we have Kiev, you can get the list of id of each region using the endpoint GET /values/citylist
"rubricList": [25], this is the field id of the category, under this id we have the heading "Marine specialties", you can get a list of the id of each category using the endpoint GET/values/rubrics
This parameter is no longer relevant and does not need to be specified in the request. At the moment, categories for vacancies are entered automatically by our system without any participation from the user, both when creating/editing vacancies using the site interface and when creating/editing using the API.

"salary": 15000, This is the salary amount field in the format of a single integer value. It is not required, but may be useful. If you need to specify the salary amount in range format “from” and “to”, then use the "salaryRange" parameter

"salaryRange": { "amountFrom": 100, "amountTo": 200000 }, this is the salary amount field in the “from” and “to” range format

"salaryDescr": "rate and bonuses", this is the comment field for the salary

"publishType": "Business", here is the type of publication that is used for the job, the types are "Business", "Optimum", "Professional", "Anonym". Indicate the one that is on the account and in which you are going to publish the vacancy.
"name": "Illusionist Diver", vacancy title
"description": "Job description text", this is a field for the job description text, at least 150 characters
"sendResumeType": "1", this is the field for setting how the vacancy will receive responses, the values can be as follows: 
1 - this is "to the \" Responses \ "section on the site and to the specified E-mail" and to the specified E-mail in the "contactEMail" parameter, 
3 - this is "only to the \" Responses \ "section on the site, 
2 - it is "direct to the questionnaire". In this case, the applicant by clicking on the "Submit resume" button when viewing a vacancy on our website will be redirected to your link. the link is specified in the "formApplyCustomUrl:" parameter: "https://www.YourLink.com/ExternalJobseekerForm
"contactEMail": " name@xxxxxxxxxxx.com ", email address to which responses will be received. Specified only if the value 1 is used in the "sendResumeType" field. If the value 3 is used in the "sendResumeType" field, then the field with the e-mail address can be omitted.
"designId": 0, this field allows you to select a template in the case of publishing a vacancy of the Professional type, it is optional. Instead of 0, substitute the number of the value of your template, you can get a list of id of each template using the endpoint GET /notebook/vacancydesign
"contactPerson": "Taras Shevchenko", this field is the name of the contact person. Specified on request
"contactPhone": "+3801111111111,+3803333333333", this is the name field of the contact person displayed in the vacancy. Specified on request

"socials": ["@Taras_Shevchenko"], this is a field of additional contact information, for example, Skype, telegram, etc., displayed in the vacancy. It is not required.

"isForStudent" , this is the option to display the "Student / No Experience Considered" flag in vacancies where true is on and false is off.
"isSpecialNeedsPeople_Enable", this is the option to display the "Consider People with Disabilities" flag in jobs where true is enabled and false is disabled.
"isHideInProfile" is the option "Don't display the job on your company's profile page" where true is enabled and false is disabled.
"endingType" is a parameter that regulates the event that will occur when the vacancy publication period expires, in which the following values are supported:
CloseAndNotify - close the vacancy and notify by email;
AutoRepublish - Post a job automatically for the next month 1 time. When the vacancy publication period expires, one service unit will be used to republish the vacancy for a new period;
*Post a vacancy automatically on a monthly basis - the setting is only available using the site interface.
"scheduleId", this is a parameter indicating the type of employment: full - 1, partial - 2, project - 5, shift - 7. There is no way to specify the nature of the work using the API; it can be specified only through the site interface.
This parameter has lost its relevance; now the type of employment and the nature of the work can be specified using the parameters "employmentTypes" and "workTypes"

"employmentTypes", is a parameter indicating the type of employment: "FullTime" - full, "PartTime" - partial, "ProjectBased" - project-based, "Shift" - shift. You can specify one or more values.

"workTypes", this is a parameter indicating the nature of the work: "Remote" - remote, "Hybrid" - hybrid, "Office" - in the office/on site. You can specify one or more values.

}

* Blocks "Advantages of the vacancy", "Photos", "Media" - can only be specified using the site interface

2. Editing a vacancy is similar to creating it, just in the "id" parameter we indicate the id of the vacancy that will be edited.
3.  With regard to the job posting process. After creating a vacancy, we get its id and using the method POST /vacancy/state change its status to Publicated, thereby publishing it.
Below is a list of statuses with which you can post, complete or delete a vacancy. 
Publicated - Post a job
Closed - Complete vacancy
Deleted - Delete vacancy
NotPublicated - Draft.
