# Work_ API (публікація вакансій, отримання відгуків)-e74558c8.docx

> Джерело: Work_ API (публікація вакансій, отримання відгуків)-e74558c8.docx (від robota.ua/work.ua). Збережено як довідка.

English: Work: API (jobs posting, getting applications)
Мета
Надати можливість публікувати вакансії та отримувати на них відгуки не тільки за допомогою сайту, а й з використанням сторонніх програм за допомогою певного протоколу — API.
Зміст
Вихідні дані
API використовує концепцію REST і технологію JSON.
Адреси https://api.work.ua/ протокол https.
Деякі ресурси будуть доступні тільки за авторизацією (публікація, відгуки).
Перша версія API працюватиме за урлом https://api.work.ua/, коли нам знадобиться нова версія апі, ми її віддаватимемо за адресою https://api.work.ua/v2/.
Авторизація
Авторизація відбувається за типом HTTP Basic Authentication.
Використовується логін і пароль користувача на сайті.
Рекомендується, включити в запит заголовок User-Agent, який буде містити в собі
назву вашої компанії;
електронну адресу користувача.
	Наприклад:
User-Agent: Freshbooks (fabian@example.com)
Ми використовуємо цю інформацію, щоб зв’язатися з вами, якщо ви робите щось не так (щоб ми могли попередити вас, перш ніж вас занесуть у чорний список)
Приклад:
curl -i --basic -u test@example.com:password123 -X GET https://api.work.ua/jobs/my
або
curl -i -H "Authorization: Basic dGVzdEBleGFtcGxlLmNvbTpwYXNzd29yZDEyMw==" -X GET https://api.work.ua/jobs/my
Відповідь сервера в разі невдалого логіна
HTTP/1.1 401 Unauthorized
Відповідь сервера після 10 спроб входу з неправильним паролем. Захист від підбору паролів
HTTP/1.1 429 Too Many Requests
Відповідь сервера, якщо користувач заблокований
HTTP/1.1 403 Forbidden
Відповідь сервера, якщо запит відправлено із неправильним методом
HTTP/1.1 501 Not implemented
Ліміти на частоту опитування
Будь ласка, обмежуйте швидкість опитування до 50 запитів на секунду, інакше IP-адресу буде заблоковано на 1 хвилину (код помилки 429).
HTTP/1.1 429 Too Many Requests
Локалізація
Щоб отримати локалізовану відповідь на кожний з ендпоінтів необхідно передати додатково заголовок X-Locale, що буде містити isoCode 'uk_UA', 'ru_RU', 'en_US'. Якщо заголовок не переданий або передана локаль не доступна, то локаль буде встановлена в 'ru_RU'.
Довідники
Довідники потрібні для зіставлення користувацьких ID-шок і ID-шок, що використовуються на нашому сервісі. Це міста, категорії, види зайнятості, досвід роботи, рівень освіти, тип публікації.
GET /dictionaries повертає об'єкт із довідниками полів і сутностей, що використовуються в нашому сервісі. Найчастіше кожен довідник складається зі списку об'єктів, що містять id та name.
Приклад: https://api.work.ua/dictionaries
Список довідників:
town — міста для розміщення резюме;
category — категорії вакансій і резюме;
jobtype — види зайнятості;
experience — досвід роботи;
education — рівень освіти;
publication_type — тип публікації вакансії;
gender — тип статі;
language — мови;
knowledge_level — рівні знання мови;
salary_resume — рівні зарплати для пошуку кандидатів.
Кожен довідник можна отримати окремо за іменем, наприклад,
GET /dictionaries/town.

Створення вакансії
Метод
POST /jobs
Необхідно надсилати заголовок авторизації. Не забудьте врахувати локалізацію.
Поля запиту
Тіло запиту необхідно передавати в стандартному application/x-www-form-urlencoded із зазначенням відповідного заголовка Content-Type.
[ ] (наприклад, у полях зайнятість або розділ) позначає, що значення цього ключа є масивом об'єктів.
 x-www-from-urlencoded format
Приклад:
curl -v --basic  -k -u [e-mail для логина]:123123 -X POST --data 'name=%D0%9F%D1%80%D0%BE%D0%B3%D1%80%D0%B0%D0%BC%D0%BC%D0%B8%D1%81%D1%82%20PHP&description=%D0%9A%D0%BE%D1%80%D0%BE%D1%82%D0%BA%D0%BE%D0%B5%20%D0%BE%D0%BF%D0%B8%D1%81%D0%B0%D0%BD%D0%B8%D0%B5%20%D0%B2%D0%B0%D0%BA%D0%B0%D0%BD%D1%81%D0%B8%D0%B8&region[id]=108&category[][id]=1&category[][id]=26&jobtype[][id]=74&jobtype[][id]=75&salary[value]=12345&&salary[comment]=%D0%B2%D0%BE%D0%B7%D0%BC%D0%BE%D0%B6%D0%BD%D0%BE%D1%81%D1%82%D1%8C%20%D0%B1%D0%BE%D0%BD%D1%83%D1%81%D0%BE%D0%B2&stud=1&show[phone]=1&publication=standart_job&experience[id]=164&languages[0][languageId]=41&languages[0][levelId]=22836&skills[0]=php&skills[1]=mysql' https://api.work.ua/jobs

201 Created — успішне додавання. У заголовку Location міститиметься посилання на додану вакансію.
400 Bad Request — помилки під час додавання вакансії. Помилки можуть бути пов'язані як з неправильними полями, так і з нестачею придбаних послуг у даного роботодавця, або перевищення лімітів на публікацію даного користувача. У тілі відповіді буде міститься опис помилки.

Редагування вакансії
Метод
PUT /jobs/<job_id>
Необхідно надсилати заголовок авторизації. Не забудьте врахувати локалізацію.
Для редагування вакансії використовуються ті самі поля, що й під час створення вакансії. При цьому передається весь набір даних як і при створенні, а старі значення перезаписуються.
Для оновлення дати публікації вакансії потрібно передати тип публікації в полі publication. При спробі переопублікувати вакансію з автоматичним продовженням терміну розміщення, коли термін продовження ще не настав, буде повернуто помилку.
Результат запиту
204 No Content — успішно відредаговано.
400 Bad Request — помилки під час редагування вакансії. Помилки можуть бути пов'язані як з невірними полями, так і з нестачею куплених послуг у даного роботодавця, або перевищення лімітів на публікацію даного користувача. У тілі відповіді буде міститься опис помилки.
Деактивація вакансії
Метод
PUT /jobs/<job_id>/close
	Необхідно надсилати заголовок авторизації
Оскільки тіло запиту порожнє, то необхідно додатково передати заголовок Content-Length зі значенням 0
Робить вакансію неактивною.
Результат запиту
204 No Content — успішно відредаговано.
Приклад:
curl -v --basic -k -u [e-mail для логіна]:123123 --header "Content-Length:0" -X PUT https://api.work.ua/jobs/1360651/close

Метод
GET /contacts/quota
Повертає список доступних відкриттів контактів для кожного регіону. Для всієї України "region": null,  для Одеської області — наприклад od, для Київської – kv. Поєднувати з конкретними містами можна через словник towns, параметр region.

Приклад відповіді:
[
  {

Відгуки
Отримання даних про всі відгуки
Метод GET /jobs/responses
Необхідно надсилати заголовок авторизації
Параметри запиту (звичайні гет параметри)
Наприклад:
GET /jobs/responses/?limit=50&before_id=123412414325
Результат запиту
200 OK — у тілі відповіді повертається JSON-об'єкт із відгуками, відсортований за порядком спадання id відгуку (від найновіших відгуків, до старих)
404 Not Found — відгуків за заданими параметрами не знайдено.
Поля відповіді
Отримання даних про відгуки на вакансію
Метод GET /jobs/<job_id>/responses
Необхідно надсилати заголовок авторизації
Параметри запиту (звичайні гет параметри)
Наприклад:
GET /jobs/12341432/responses/?limit=50&before_id=123412414325
Результат запиту
200 OK — у тілі відповіді повертається JSON-об'єкт із відгуками на вакансію, відсортований за порядком спадання id відгуку (від найновіших відгуків, до старих)
400 Bad Request — при спробі відкрити чужу вакансію
404 Not Found — відгуків за заданими параметрами не знайдено.
Поля відповіді
Завантаження файлу відгуку
Завантаження файлу, надісланого під час відгуку. Працює тільки для відгуків, у яких поле with_file дорівнює 1.
Метод GET /response_files/<job_id>/<response_id>
Необхідно надсилати заголовок авторизації.
Параметри запиту:
Наприклад:
GET /response_files/12345/54321
Результат запиту
200 OK — у тілі відповіді повертається вміст файлу, який користувач відправив під час відгуку.
400 Bad Request — при спробі відкрити не свою вакансію.
404 Not Found — відгук не знайдено або для відгуку немає файлу.
