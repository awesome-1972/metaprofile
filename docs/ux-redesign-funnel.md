# UX/UI редизайн екрана вакансії (воронки найму)

Документ-пропозиція. Код не змінюється — це план для подальшого впровадження.
Орієнтир — конкурент **The AIHA**: ліва панель фільтрів + чистий горизонтальний
kanban з мінімалістичними картками та drag-and-drop.

Головний екран: `src/pages/ats/VacancyDetailPage.tsx`.
Дотичні: `src/components/ats/PhaseNav.tsx`, `StuckPanel.tsx`, `FunnelEditor.tsx`,
`RequisitionPanel.tsx`, `PreparationPanel.tsx`.

---

## 1. Що саме перевантажує екран

Екран показує все й одразу, у чотирьох «поверхах» над самою воронкою, а вже
всередині воронки — ще один рівень дублювання. Конкретно:

**Шапка (`VacancyDetailPage.tsx`, рядки 553–646).** На одному блоці зібрано:
кнопку «До списку вакансій», заголовок, посилання на проект, посилання на клієнта,
локацію, бейдж статусу, тип зайнятості + к-сть позицій, окремий рядок «Відповідальний
рекрутер» із `Select` і бейджем, плюс праворуч кнопки «Масова розсилка» і «Додати
кандидата». Це 9+ елементів у першому екрані ще до контенту.

**RequisitionPanel (рядки 648–678).** Повноцінна `Card` із заголовком, абзацом-описом,
блоком коментаря, gate-hint і рядком кнопок — показується **завжди**, навіть коли
заявка вже `approved` і жодної дії не потрібно. Забирає багато вертикалі даремно.

**7 вкладок в один ряд (рядки 680–689):** Етапи пошуку / Списки / Бріф / Компетенції /
Порівняння / Звіти / Файли. Це змішані сутності (робота з людьми, підготовчі артефакти,
аналітика, документи) в одному пласкому рівні.

**Дві попереджувальні `Alert` поспіль (рядки 692–710):** «Підготовка не завершена» і
«Стадії без етапу» — обидві завжди зверху над воронкою, відсувають робочу зону вниз.

**Подвійна навігація по етапах.** `PhaseNav` (рядки 731–741) — горизонтальний степер із
широких карток (кожна `w-48`, зі статусом, лічильником, дедлайном і рядком кнопок статусу
під ним). А нижче, у «наскрізній воронці» (рядки 820–863), **ще раз** промальовуються всі
етапи кольоровими заголовками-кнопками з крапкою-світлофором і лічильником. Тобто етапи
відрендерені двічі, різними способами.

**Тулбар над воронкою (рядки 762–804):** перемикач Kanban/Таблиця + «Імпорт лонг-листа з
Excel» + `PhaseExportButton` + `FunnelEditor` («Налаштувати воронку») — 4–5 контролів у ряд.

**StuckPanel (рядок 816)** — ще одна згортна картка над воронкою.

**Найважче — картка кандидата (рядки 903–1094).** На одній маленькій картці:
- чекбокс (у bulk-режимі),
- ім'я-посилання,
- джерело,
- SLA-крапка + «N дн. на стадії»,
- бейдж найближчого інтерв'ю,
- бейдж Long/Short list + інлайн-посилання-перемикач списку («→ Short list» / «прибрати»),
- кнопка на всю ширину «Оцінка компетенцій»,
- кнопка на всю ширину «Зустріч»,
- сітка 2×1: «Далі» + «Відмова»,
- рядок керування стадією: ‹ + `Select` усіх стадій + ›.

Це **7–9 інтерактивних контролів на кожній картці**. Помножити на десятки карток у
кількох колонках — і виникає стіна кнопок. Це прямо протилежне мінімалістичній картці
AIHA (ім'я + стадія + ключове).

**Немає лівої панелі фільтрів взагалі.** Пошук/фільтрація кандидатів у воронці відсутні;
пошук є лише в діалозі «Додати кандидата». Світлофор SLA існує (крапки), але за ним не
можна відфільтрувати — лише візуально шукати очима.

## 2. Новий layout (ціль)

Двоколонкова робоча зона під компактною шапкою:

```
┌──────────────────────────────────────────────────────────────┐
│  ← Назва вакансії  [статус]  · клієнт · локація   [Заявка ✓] [⋯]│  компактна шапка
├───────────────┬──────────────────────────────────────────────┤
│  ФІЛЬТРИ       │   Воронка / Підготовка / Аналітика / Файли     │  4 групи вкладок
│  🔍 пошук      │  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐          │
│  ▸ Етапи ☑     │  │Стадія│ │Стадія│ │Стадія│ │Стадія│          │
│  ▸ SLA 🔴🟡🟢  │  │ ▓▓▓  │ │ ▓▓   │ │ ▓    │ │      │          │  чистий kanban
│  ▸ Списки      │  │ ▓▓   │ │      │ │      │ │      │          │  мінім. картки
│  ▸ Джерело     │  └──────┘ └──────┘ └──────┘ └──────┘          │
│  ▸ Рекрутер    │                                                │
└───────────────┴──────────────────────────────────────────────┘
```

### 2.1. Ліва панель фільтрів (нова, за зразком AIHA)

Новий компонент, напр. `src/components/ats/FunnelFilters.tsx`. Згортна (на вузьких
екранах — у `Sheet`/офф-канвас). Вміст:

- **Пошук** за ім'ям/email/джерелом (інпут згори).
- **Етапи** — чекбокси етапів пошуку (заміняють клікабельний степер `PhaseNav` як
  основний спосіб фільтрації; за замовчуванням активний етап позначений).
- **Рейтинг збігу / SLA-світлофор** — три перемикачі 🔴 🟡 🟢 (аналог «повзунка рейтингу»
  AIHA). Дані вже рахуються — `candidateSla()` у `use-sla`. Дає фільтр «показати лише
  завислих».
- **Списки** — Long list / Short list / без списку.
- **Джерело** — з `useCandidateSources`.
- **Стиль роботи / локація** — is_remote / локація вакансії (для мульти-локаційних).
- **Відповідальний рекрутер** — з `useProfilesList`.

Фільтр застосовується до `applicationsByStage` перед рендером колонок. `StuckPanel`
стає надлишковим як окремий блок — його роль перебирає фільтр SLA (можна лишити
компактний лічильник «N завислих» у шапці панелі фільтрів).

### 2.2. Спрощена картка кандидата (kanban)

Мінімальна картка показує лише:
- **ім'я** (клік — відкриває деталі кандидата),
- **ключове** — джерело + SLA-крапка з «N дн.»,
- максимум **один** бейдж стану: Short list (або найближче інтерв'ю, якщо є),
- зона для drag-and-drop (як зараз).

Усе інше ховається:

| Контрол зараз на картці | Куди переносимо |
|---|---|
| «Оцінка компетенцій» | у **⋯ (kebab-меню)** картки → `DropdownMenu` |
| «Зустріч» | у kebab-меню |
| «Далі» / «Відмова» | у kebab-меню (розділ «Дії етапу») |
| ‹ › + `Select` стадії | **прибрати** — рух робиться drag-and-drop; точний вибір стадії лишити в kebab як «Перемістити в…» |
| Перемикач Long/Short інлайн-посиланням | у kebab («Додати в short list» / «Прибрати зі списку») |
| Чекбокс bulk | лишається, але видимий **лише** у режимі масової розсилки |

Тобто на картці — 0–1 кнопка (kebab «⋯») замість 7–9. Наведення/клік по «⋯» відкриває
контекстні дії. Це і є картка рівня AIHA.

Технічно: додати `src/components/ui/dropdown-menu.tsx` (`npx shadcn-ui add dropdown-menu`)
і винести тіло картки в окремий компонент `src/components/ats/FunnelCard.tsx`, щоб
`VacancyDetailPage` не роздувався.

### 2.3. Деталі кандидата — бічний drawer замість переходу

Клік по картці зараз веде на `/ats/candidates/:id` (повний перехід). Краще — відкривати
**бічну панель** (`Sheet`/drawer) з деталями заявки: тут живуть оцінка компетенцій,
історія стадій, планування зустрічі, кнопки «Далі/Відмова». Тоді картка чиста, а всі
важкі дії — в одному передбачуваному місці, без втрати контексту воронки.

### 2.4. Прибрати подвійну навігацію по етапах

Зараз етапи рендеряться двічі: `PhaseNav` (степер) + кольорові заголовки в «наскрізній
воронці». Обрати **одне джерело правди**:
- етапи як **чекбокси у лівій панелі фільтрів** (керують видимістю колонок),
- у самому kanban етап позначається лише кольоровою «шапкою-роздільником» над групою
  його стадій (тонка кольорова смужка + назва + лічильник), без окремого клікабельного
  степера зверху.

`PhaseNav` можна лишити лише для режиму керування статусом етапу (pending/active/done)
— але сховати ці кнопки в компактний `Select`/popover, а не рядок з трьох кнопок.

### 2.5. Компактна шапка + Requisition як чип

- Заголовок, статус, клієнт, локація — **один рядок**. Тип зайнятості, к-сть позицій,
  рекрутер — прибрати в popover «Деталі вакансії» або на вкладку «Підготовка».
- `RequisitionPanel` **згорнути до чипа** у шапці: `[Заявка: Затверджено ✓]`. Повна
  картка з описом і кнопками показується (розкривається) лише коли є дія:
  `draft`, `pending_approval`, `changes_requested`, `rejected`. У стані `approved` —
  лише чип + popover з датою/коментарем. Це прибирає найбільший «мертвий» блок.
- «Масова розсилка» і «Додати кандидата» — лишити «Додати кандидата» головною кнопкою,
  «Масову розсилку» перенести в **⋯ overflow** шапки (це рідша дія).

### 2.6. Тулбар воронки — в overflow

Перемикач Kanban/Таблиця лишити (сегмент-контрол). «Імпорт з Excel», `PhaseExportButton`,
«Налаштувати воронку» (`FunnelEditor`) — сховати під одну кнопку **⋯** праворуч над
воронкою. Це нечасті адмін-дії.

### 2.7. Групування 7 вкладок у 4

| Нова вкладка | Що всередину |
|---|---|
| **Воронка** | поточні Етапи пошуку (kanban/таблиця) + Списки як під-вигляд |
| **Підготовка** | Бріф + Компетенції (сьогодні `PreparationPanel` уже має свій чеклист — злити) |
| **Аналітика** | Порівняння + Звіти |
| **Файли** | без змін |

Alerts («Підготовка не завершена», «Стадії без етапу») — прибрати з-над воронки в
ненав'язливий інлайн-банер усередині відповідних вкладок або в чип-попап.

## 3. Поетапний чек-лист впровадження (від дешевого до складного)

**Етап A — «полегшити картку» (найдешевше, найбільший ефект).**
1. Додати shadcn `dropdown-menu`: `npx shadcn-ui@latest add dropdown-menu`.
2. Винести тіло картки з `VacancyDetailPage.tsx` (рядки ~903–1094) у новий
   `src/components/ats/FunnelCard.tsx`.
3. На картці лишити: ім'я, джерело+SLA, один бейдж, drag. Решту (Оцінка, Зустріч,
   Далі, Відмова, перемикач списку, «Перемістити в…») — у `DropdownMenu` («⋯»).
4. Прибрати з картки ‹ › + `Select` стадії (рух — drag-and-drop; точний вибір — у kebab).

**Етап B — прибрати «мертві» блоки зверху.**
5. `RequisitionPanel`: показувати повну картку лише в станах, що потребують дії; інакше —
   чип у шапці + popover. Правка обгортки в `VacancyDetailPage.tsx` (рядки 648–678) і/або
   пропс-режим `compact` у `RequisitionPanel.tsx`.
6. Alerts (рядки 692–710) — прибрати з топу, зробити інлайн-банерами/чипами.
7. Тулбар воронки (рядки 762–804): Імпорт/Експорт/`FunnelEditor` — у overflow «⋯».
   «Масова розсилка» з шапки — теж в overflow.

**Етап C — прибрати дублювання етапів.**
8. Прибрати подвійний рендер: лишити або степер, або кольорові заголовки в kanban.
   Рекомендація — кольорові роздільники в kanban, статус етапу — в компактний popover.
   Спрощення `PhaseNav.tsx` або його виведення з основного потоку.

**Етап D — ліва панель фільтрів (найбільша робота, ядро редизайну).**
9. Новий `src/components/ats/FunnelFilters.tsx`: пошук, чекбокси етапів, SLA-світлофор,
   списки, джерело, рекрутер. На мобільному — у `Sheet`.
10. Прокинути стан фільтрів у `VacancyDetailPage`, застосувати до `applicationsByStage`
    перед рендером колонок. `StuckPanel` замінити лічильником у панелі фільтрів.
11. Перевести layout вкладки «Воронка» на дві колонки (фільтри + kanban).

**Етап E — деталі кандидата в drawer + регрупування вкладок.**
12. `Sheet`-drawer деталей заявки (компетенції, зустріч, історія, Далі/Відмова) замість
    повного переходу на сторінку кандидата.
13. Згрупувати 7 вкладок у 4 (Воронка / Підготовка / Аналітика / Файли).

## 4. Топ-3 принципи

1. **Одна дія на видимому рівні, решта — на глибині.** Картка й шапка показують стан і
   один головний CTA; усі вторинні дії — у kebab/drawer/overflow.
2. **Фільтр замість «показати все».** Ліва панель (з SLA-світлофором) робить те, що зараз
   роблять `StuckPanel` + подвійна навігація по етапах, але без візуального шуму.
3. **Не рендерити нуль-інформації.** Requisition у стані approved, порожні alert-и,
   дубльований степер — усе це прибираємо або згортаємо.
